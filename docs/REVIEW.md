# 리뷰 기준 (리뷰어: Claude Sonnet)

PR 하나를 리뷰할 때 아래 순서로 확인한다. 명세서(`docs/tasks/Txx-*.md`)와 `AGENTS.md`가 기준이다.

## 심각도 표기
- 🔴 **필수 수정**: 버그, 데이터 손실, 보안 문제, 수용 기준 미충족. 머지 전에 반드시 고친다.
- 🟡 **권장**: 유지보수성, 테스트 부족, 사소한 UX 문제. 이 PR에서 고치는 게 좋다.
- 🟣 **범위 밖**: 기존 코드 문제나 새 아이디어. 이 PR에서 고치지 말고 백로그로 보낸다.

## 1. 수용 기준
- [ ] 명세서의 수용 기준을 하나씩 대조했고, 빠진 항목이 없다.
- [ ] 명세서의 "범위 제외"를 구현하지 않았다(범위 확장 금지).

## 2. 정확성
- [ ] 연산 생성기: 정답이 실제로 맞는가, 학년 범위를 벗어나는 수(음수, 너무 큰 수, 0으로 나누기)가 나오지 않는가.
- [ ] 채점: 맞는 답을 오답으로 처리하는 경우(분수 동치, 소수 표기, 공백)가 없는가.
- [ ] 미션 진행은 `applyProgress()`를 거쳐 별, 연속 학습일, 쿠폰이 한 번씩만 처리되는가. React StrictMode에서 두 번 실행돼도 결과가 같은가.
- [ ] 날짜는 `toDateKey()`(로컬 시간)를 쓰는가. UTC 때문에 자정 근처에 날짜가 밀리지 않는가.

## 3. 데이터 안전
- [ ] 저장 스키마 변경이 있으면 `normalizeState()`가 이전 데이터를 살리는가. 관련 테스트가 있는가.
- [ ] 콘텐츠 id(단어, 문장)를 바꾸거나 중간에 끼워 넣어 기존 SRS 기록을 깨지 않았는가.
- [ ] 백업과 복원(JSON)에 새 필드가 포함되는가.

## 4. 보안과 개인정보 (AI 작업에서 특히)
- [ ] API 키, 토큰이 클라이언트 번들, 저장소, 로그에 없다.
- [ ] 프록시는 인증(가족 토큰) 없이는 AI API를 호출하지 않는다. CORS는 앱 주소만 허용한다.
- [ ] 하루 사용량 제한이 서버(프록시)에서 강제된다(클라이언트 제한만으로는 부족).
- [ ] 아이 대화 프롬프트에 안전 지침(나이에 맞는 주제, 개인정보 묻지 않기)이 있고, 아이 메시지는 모더레이션을 거친다.
- [ ] 외부로 보내는 데이터가 명세서에 적힌 것뿐이다(이름 대신 프로필 id, 학년 등 최소한).

## 5. 아이 UX
- [ ] 터치 영역이 충분히 크고(48px 이상), 375px 폭에서 레이아웃이 깨지지 않는다.
- [ ] 문구가 짧고, 초3이 읽을 수 있는 수준이다. 오답일 때 탓하는 말투가 아니다.
- [ ] 로딩, 실패(네트워크, 음성 인식 미지원) 상태에서 아이가 막히지 않는 길이 있다.
- [ ] 다크 모드에서 글자가 읽힌다.

## 6. 코드 품질과 테스트
- [ ] 새 로직은 `lib/`나 `content/`의 순수 함수이고 Vitest 테스트가 있다.
- [ ] 테스트를 지우거나 skip하지 않았다.
- [ ] 불필요한 의존성, 죽은 코드, 디버그 로그가 없다.
- [ ] `npm run typecheck && npm test && npm run build` 통과를 CI나 로컬 실행 결과로 확인했다.
