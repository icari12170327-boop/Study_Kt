# T06 — 독서노트에서 AI 복습 질문 만들기

- 상태: 준비됨
- 단계: 2
- 선행 작업: T02
- 예상 분량: 반나절

## 목표
독서노트(보호자)나 독서록(아이)을 저장할 때 "AI로 복습 질문 만들기"를 누르면, 요약 내용을 바탕으로 질문과 답 후보가 나오고, 고른 것만 복습 카드로 저장된다.

## 배경
1단계 독서노트는 질문과 답을 직접 써야 해서 손이 많이 간다. AI가 초안을 만들고 사람이 고르면 꾸준히 쓰기 쉽다.

## 범위
**포함**
- `NoteEditor`의 질문 목록 위에 "🤖 질문 만들기" 버튼 (AI 설정이 있고 요약이 40자 이상일 때만 활성)
- Worker `/api/generate` `kind: 'reading-quiz'`, 입력 `{ title, author, summary, level, count }` (count 기본 5)
- 응답 스키마: `{ cards: { q: string; a: string; type: 'fact' | 'why' | 'apply' }[] }`
  - 보호자: 핵심 개념(fact), 저자의 주장 이유(why), 내 일에 적용(apply)을 섞는다
  - 아이: 줄거리 사실 확인(fact) 위주, 등장인물 마음(why) 1개, 답은 한 문장
- 후보 목록에서 체크해서 고르고, 고친 뒤 추가 → 기존 `cards`에 합쳐 저장
- 요약에 없는 내용은 만들지 않도록 프롬프트에 명시

**제외**
- 책 내용 검색이나 웹 검색
- 사진(책 페이지)에서 텍스트 인식

## 설계
- 질문 후보 상태는 편집 화면 안에서만 관리하고, 저장할 때 기존 흐름(`update`)을 그대로 탄다.
- 같은 질문이 이미 있으면(공백, 대소문자 무시) 후보에서 뺀다. 순수 함수 `dedupeCards(existing, candidates)`로 만든다.

## 수용 기준
- [ ] 요약을 쓰고 "질문 만들기"를 누르면 5개 안팎의 후보가 나온다.
- [ ] 후보를 고치고 골라서 추가할 수 있고, 저장 후 복습에 나온다.
- [ ] 아이 프로필과 보호자 프로필의 질문 수준이 다르다.
- [ ] AI 미설정, 오류, 사용량 초과 상태에서 버튼이 비활성되거나 이유가 표시된다.
- [ ] `npm run typecheck && npm test && npm run build` 통과
