# T05 — 수학 도전: 레벨, 숫자 키패드, 꼼수 방지

- 상태: 완료 (PR #8)
- 단계: 3
- 선행 작업: 없음 (T02와 병행 가능, AI 불필요)

## 목표
1단계 연산을 "수학 도전"으로 바꾼다. 하루 20문제를 화면 숫자 키패드로 풀고, 결과에 따라 다음 날 레벨이 자동으로 오르내린다. 일부러 틀려서 쉬워지게 하는 꼼수는 통하지 않는다.

## 배경
원글: 둘째가 일부러 틀려 난이도를 낮추자 "5초 안에 틀린 건 찍기로 보고 제외", "최근 7일 최고 기록보다 한 단계 아래로는 안 내려감", "1분 넘게 딴짓한 시간은 제외"를 넣었더니 그냥 푸는 게 제일 빨라졌다.

## 설계

### 레벨 표
각 레벨은 주 단원과 복습 단원을 가진다. 문제의 70%는 주 단원, 30%는 아래 레벨 단원에서 고르게 낸다.

**3학년**
| 레벨 | 주 단원 (skill id) |
|---|---|
| 1 | 두 자리 덧셈·뺄셈 `g2-addsub2` (새로 만듦), 곱셈구구 `g2-times` (새로 만듦) |
| 2 | 세 자리 덧셈 `g3-add3` |
| 3 | 세 자리 뺄셈 `g3-sub3` |
| 4 | 곱셈구구 범위 나눗셈 `g3-div-basic` |
| 5 | 두 자리 × 한 자리 `g3-mul2x1` |
| 6 | 세 자리 × 한 자리 `g3-mul3x1` |
| 7 | 두 자리 ÷ 한 자리 (나머지) `g3-div-rem` |
| 8 | 두 자리 × 두 자리 `g3-mul2x2` |
| 9 | 3학년 전체 섞기 + 빈칸 추론 `g3-missing` (새로 만듦: `□ + 245 = 612`, `□ × 7 = 56`) |

**5학년**
| 레벨 | 주 단원 |
|---|---|
| 1 | 혼합 계산 `g5-mixed` |
| 2 | 최대공약수, 최소공배수 `g5-gcd`, `g5-lcm` |
| 3 | 약분 `g5-reduce` |
| 4 | 분수 덧셈 `g5-frac-add` |
| 5 | 분수 뺄셈 `g5-frac-sub` |
| 6 | 어림하기 `g5-round` |
| 7 | 분수의 곱셈 `g5-frac-mul` |
| 8 | 소수의 곱셈 `g5-dec-mul` |
| 9 | 평균 + 5학년 전체 섞기 `g5-avg` |

보호자가 켠 단원(`mathSkills`)은 이제 쓰지 않는다. 설정 화면의 단원 칩은 "레벨 수동 조정"으로 대체한다.

### 기록
```ts
interface MathAttempt {
  skill: string;
  correct: boolean;
  activeMs: number;   // 유휴 구간을 뺀 풀이 시간
  guessed: boolean;   // !correct && activeMs < 5000
}
interface MathLevelState {
  level: number;                       // 기본: 초3=3, 초5=4 (지금 학기 진도 근처)
  lastEvaluated?: string;              // 마지막 평가 날짜
  history: { date: string; level: number; counted: number; correct: number; guesses: number; medianSec: number }[]; // 최근 30일
}
// ProfileData.math: MathLevelState
// DayLog.mathAttempts: MathAttempt[]
```

### 시간 측정
- 문제가 나온 시각부터 확인을 누른 시각까지. 그 사이 키패드 입력 간격이 60초를 넘는 구간은 빼고, 60초만 센다. 순수 함수 `activeDuration(events: number[], idleCapMs = 60000)` (events = 문제 표시 시각 + 키 입력 시각들 + 제출 시각).

### 하루 평가 `evaluateLevel(state, lastDay, today)` (순수 함수)
그날 첫 수학 세션을 시작할 때, 아직 평가하지 않은 가장 최근 학습일의 기록으로 평가한다.
1. 반영 문제 = 찍기가 아닌 시도. 반영 문제가 10개 미만이면 레벨 유지.
2. 정답률 = 정답 / 반영 문제. 중앙값 시간 = 정답 문제의 `activeMs` 중앙값.
3. 정답률 ≥ 90% 그리고 중앙값 ≤ 레벨 목표 시간(레벨 표에 `targetSec`, 기본 25초) → +1
4. 정답률 < 60% → -1
5. 그 외 유지
6. 바닥 = (최근 7일 최고 레벨) - 1, 천장 = 마지막 레벨. 범위 밖이면 자른다.
7. 결과를 `history`에 추가.

### 찍기 대응
- 한 세션에서 찍기가 3번 나오면 부드러운 안내: "천천히 생각해도 괜찮아! 빨리 틀리면 점수에 안 들어가 🙂"
- 보호자 현황에 날짜별 찍기 횟수 표시.

### `NumberPad` 컴포넌트
- 0~9, ⌫, 확인. 소수 문제에만 `.` 키. 분수와 몫/나머지 문제는 칸을 눌러 포커스를 옮기고(또는 "다음 칸" 키) 키패드로 입력.
- 입력 칸은 `readOnly` + `inputMode="none"`으로 시스템 키보드를 막는다. 물리 키보드(DeX) 입력도 그대로 받는다.
- 버튼 최소 64px, DeX 마우스 클릭과 터치 모두 고려.

## 수용 기준
- [ ] 수학 미션은 하루 20문제(보호자 설정 가능)이고, 화면 키패드로 답한다. 시스템 키보드가 뜨지 않는다.
- [ ] 레벨 표의 단원이 70/30 비율로 출제된다(테스트).
- [ ] `evaluateLevel`이 위 규칙대로 동작한다: 승급, 강등, 유지, 바닥, 찍기 제외, 10문제 미만 유지(테스트).
- [ ] `activeDuration`이 60초 넘는 공백을 빼고 센다(테스트).
- [ ] 같은 날 여러 번 세션을 시작해도 평가는 하루 한 번만 된다.
- [ ] 보호자 화면에 최근 14일 레벨 변화와 찍기 횟수가 보이고, 레벨을 직접 바꿀 수 있다.
- [ ] 1단계 기록(오답노트, 별)이 유지되고, `math` 상태 기본값이 채워진다(`normalizeState` 테스트).
- [ ] `npm run typecheck && npm test && npm run build` 통과

## 테스트
