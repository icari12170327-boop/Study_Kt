# T04 — AI 비즈니스 롤플레이와 "내 표현" 단어장 (보호자)

- 상태: 준비됨
- 단계: 2
- 선행 작업: T02 (T03의 대화 화면 컴포넌트를 재사용하면 좋음)
- 예상 분량: 하루

## 목표
보호자가 회의, 협상, 발표 질의응답 같은 비즈니스 상황을 AI 상대와 영어로 연습하고, 끝나면 더 자연스러운 표현을 받아 **"내 표현" 단어장**에 저장해 간격 반복으로 복습한다.

## 배경
보호자(만 45세)의 관심사는 비즈니스 영어회화와 AI다. 1단계의 비즈니스 문장 섀도잉은 듣고 따라 하기뿐이라, 실제로 말을 만들어 내는 연습이 필요하다.

## 범위
**포함**
- 보호자 홈에 "💼 롤플레이" 진입 버튼 (미션 타입 `talk`를 재사용, 보호자 기본값은 켜짐, 목표 8턴)
- 시나리오 (Worker `prompts.ts`, 최소 6개):

| id | 상황 | AI 역할 | 목표 |
|---|---|---|---|
| `biz-standup` | 주간 업무 공유 회의 | 해외 팀 매니저 | 진행 상황, 지연 이유, 다음 계획 보고 |
| `biz-negotiation` | 납품 단가 협상 | 공급업체 영업 담당 | 가격, 물량, 납기 조건 조율 |
| `biz-presentation-qa` | 발표 후 질의응답 | 까다로운 임원 | 질문을 받아 명확히 답하기 |
| `biz-ai-adoption` | 사내 AI 도입 논의 | 회의적인 동료 | 활용 사례, 리스크, 시범 사업 제안 |
| `biz-smalltalk` | 해외 출장 첫 미팅 전 스몰토크 | 거래처 담당자 | 자연스러운 대화 시작과 전환 |
| `biz-escalation` | 문제 상황 보고 | 고객사 담당자 | 사과, 원인, 해결 일정 |

- 대화 화면은 T03 컴포넌트를 재사용하되, 보호자 모드에서는 **텍스트 입력을 기본**, 음성은 선택
- "더 나은 표현" 버튼: 방금 보낸 문장을 더 자연스러운 비즈니스 표현 2개로 바꿔 줌(대화 흐름과 별개 요청)
- 종료 피드백 (`kind: 'roleplay-feedback'`): 전체 평가 한 줄(한국어), 고친 표현 최대 5개(`said`, `better`, `why`), 다음에 써 볼 핵심 표현 3개
- 고친 표현과 핵심 표현에 "내 표현에 저장" 버튼 → 사용자 단어장 덱 `my-phrases`에 카드 추가
- 사용자 정의 덱: `ProfileData.customCards: { id: string; en: string; ko: string; source: string; createdAt: string }[]`. 단어 세션과 말하기 세션 덱 목록에 `my-phrases`가 나타난다.

**제외**
- 이메일 첨삭 (백로그)
- 음성 발음 평가

## 설계
- 비즈니스 시스템 프롬프트 요구사항: 상대 역할을 일관되게 연기, 답장은 2~4문장, 사용자가 너무 짧게 답하면 구체적으로 되묻기, 대화 중에는 교정하지 않고 피드백 때 모아서
- `my-phrases` 덱은 `VOCAB_DECK_MAP`처럼 정적 목록이 아니므로, 덱을 찾는 함수 `getVocabCards(deckId, data)`를 만들어 정적 덱과 사용자 덱을 같은 방식으로 다룬다. `buildVocabSession`과 `SpeakingSession`이 이 함수를 쓰도록 바꾼다.
- 사용자 카드 id는 `uid()`로 만들고, SRS 키는 기존 규칙(`vocab:my-phrases:<id>`, `speak:my-phrases:<id>`)을 따른다.
- 카드 삭제 시 해당 SRS 키도 지운다.

## 수용 기준
- [ ] 보호자가 시나리오 6개 중 하나를 골라 8턴 이상 대화할 수 있다.
- [ ] "더 나은 표현"이 대화 맥락을 유지한 채 동작한다.
- [ ] 피드백의 표현을 "내 표현"에 저장하면, 다음 단어 세션과 말하기 세션에 등장한다.
- [ ] 보호자 설정에서 `my-phrases` 덱을 켜고 끌 수 있고, 카드 목록을 보고 삭제할 수 있다.
- [ ] 백업과 복원에 `customCards`가 포함된다.
- [ ] 아이 프로필에서는 비즈니스 시나리오가 보이지 않는다.
- [ ] `npm run typecheck && npm test && npm run build` 통과

## 테스트
- `getVocabCards`가 정적 덱과 사용자 덱을 모두 반환하는지, 보기 4개를 만들 카드가 부족할 때(사용자 카드 3장 이하) 다른 덱에서 오답 보기를 채우는지
- 카드 삭제 시 SRS 키 정리
- `normalizeState`가 `customCards` 기본값을 채우는지

## 리뷰 포인트
- 단어 세션의 보기 생성이 사용자 덱 카드 수가 적을 때 깨지지 않는지
- 롤플레이 프롬프트가 사용자를 대화 중에 계속 교정해서 흐름을 끊지 않는지
