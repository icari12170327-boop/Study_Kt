# T26 — 첫째 수학 빙고판 6×6 → 5×5

- 상태: 준비됨 · 2026-10-10 작성 · T24a(PR #63) 머지 후 진행
- 단계: 유지 (실사용 수정)
- 선행 작업: T16, T24a
- 예상 분량: 반나절

## 목표
첫째의 수학 빙고판을 6×6에서 5×5로 줄인다. 숫자 36개를 훑느라 눈이 돌아가서 못 풀겠다는 요청을 반영한다. 난이도는 판 크기가 아니라 숫자 범위와 곱셈 목표로 유지한다.

## 배경
- 2026-10-10 첫째 의견: "빙고판이 가로·세로 한 줄씩 늘어나서 눈이 돌아간다. 줄여 달라."
- 코드 확인: 빙고판은 T16(PR #25)부터 첫째 6×6, 둘째 5×5였고 그 뒤로 바뀌지 않았다. 판이 실제로 늘어난 것은 아니다. 다만 T20b에서 스도쿠를 5×5로 줄인 뒤라 빙고 6×6이 상대적으로 크게 느껴졌을 수 있다. T24a에서 큰 화면의 판이 커진 것도 영향을 줬을 수 있다.
- 지금 코드: `src/content/math/bingo.ts`
  - `generateBingoBoard`의 `size = level === 'g3' ? 5 : 6`
  - `candidates`의 합 목표 범위가 판 크기(`board.size === 5 ? 6..24 : 10..50`)에 묶여 있다. 판 크기만 바꾸면 첫째가 둘째 범위(6~24)를 받게 된다.
  - 예비 판 `FALLBACK_G5`가 6×6이고, 예비 목표 합(38, 43, 37, 32, 46)과 곱(110, 300, 108, 360)이 그 판 기준이다.
  - 최고 기록 `bingo.best`는 제한 시간(초) 키로만 저장한다. 판 크기가 달라지면 예전 6×6 기록과 비교가 맞지 않는다.

## 범위
**포함**
- 첫째(g5) 판을 5×5로 바꾼다. 둘째(g3)는 그대로 둔다.
- 목표 범위를 판 크기가 아니라 **레벨**로 정한다.
  - g3: 합 6~24, 곱 없음 (지금 그대로)
  - g5: 합 10~50, 곱 12~400 (지금 첫째 범위 그대로)
  - 숫자 범위도 그대로다. g5는 1~20이고, 곱 목표가 있으면 일부 칸을 1~12로 둔다. `i < 18` 기준은 25칸에 맞게 비율로 조정한다(예: 절반인 12칸).
- g5 5×5 예비 판과 예비 목표를 새로 만든다. 테스트로 목표마다 정답 줄이 1~4개 있는지 검증한다.
- **생성 성공률 확인**: 5×5는 줄 수가 적어서 곱 목표(2~3개, 많이는 4개)와 서로 다른 정답 줄 조건을 만족하기 어려울 수 있다.
  - 시드 500개로 `productMix`(off, few, normal, many)마다 예비 판으로 떨어지는 비율을 재고 PR에 적는다.
  - 비율이 5%를 넘으면 시도 상한, 숫자 분포, many의 곱 개수 중에서 가장 작은 변경으로 낮춘다. 바꾼 내용은 PR에 적는다.
- **최고 기록**: 새 기록 키에 판 크기를 넣는다. 예: `"5x5-120"`. 키 형식이 이미 다르면 같은 원칙으로 한다.
  - 예전 키(`"120"`)는 6×6 기록으로 보고 지우지 않는다.
  - 화면에서는 "예전 6×6 기록"으로 따로 보이거나 숨긴다. 새 5×5 최고 기록 비교에는 쓰지 않는다.
  - `normalizeState`와 백업 테스트를 붙이고, version 2를 유지한다.
- 진행 중인 판을 저장하는 기능이 있으면 6×6 진행 판은 버리고 새 판을 시작한다. 없으면 해당 없음.
- 화면 스타일은 T24a의 판 크기 규칙을 그대로 쓴다. `.bingo-size-6` 전용 스타일이 첫째에게 더 이상 쓰이지 않으면 정리한다.

**제외**
- 목표 개수(5개), 제한 시간, 힌트, 별·쿠폰 계산 변경
- 둘째 판 변경
- 새 게임 규칙

## 수용 기준
- [ ] 첫째로 빙고를 시작하면 5×5 판이 나오고, 목표는 합 10~50과 곱 12~400 범위 안이다(테스트). 둘째 판은 그대로 5×5, 합 6~24다.
- [ ] 모든 `productMix`에서 목표 5개가 나오고, 목표마다 정답 줄이 1~4개다. 곱 목표 줄에는 1이 없다(시드 여러 개로 테스트).
- [ ] 예비 판 비율을 PR에 적었고 5% 이하다.
- [ ] 예전 6×6 최고 기록은 남아 있지만 새 5×5 기록과 섞여 비교되지 않는다. `normalizeState`와 백업 테스트가 있다.
- [ ] 390×844, 1333×800, 2560×1440에서 판 전체와 목표 목록이 한 화면에 보이고 가로 넘침이 없다.
- [ ] `npm run lint && npm run typecheck && npm test && npm run build` 통과

## 리뷰 포인트
- 판만 작아지고 난이도는 첫째 수준(큰 수, 곱셈 목표)으로 유지되는지
- 5×5에서 목표가 너무 쉽게 겹치거나, 정답 줄이 지나치게 많아지지 않는지
- 예전 기록이 사라지지 않는지
- 실사용 확인(보호자): 첫째가 2~3판 해 보고 눈이 덜 피로한지, 너무 쉬워지지 않았는지
