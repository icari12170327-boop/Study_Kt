# T21 — 도형 규칙 다시 만들기: 속성마다 다른 규칙

- 상태: 준비됨 · **다음**
- 단계: 3 (T06b 개선)
- 선행 작업: T06b (도형 규칙 첫 버전)
- 예상 분량: 하루

## 배경 (2026-10-10 보호자 실사용, 첫째)
- 지금 `src/content/puzzles/pattern.ts`는 처음 2~4칸(묶음)을 **통째로 반복**한다. 모양·색·개수가 한 묶음에 묶여 함께 움직인다.
- 그래서 "앞에서 묶음 길이만큼 전과 똑같은 것"을 고르는 요령 하나로 ★1~★5가 모두 풀린다. 난이도가 올라도 묶음 길이와 속성 수만 늘 뿐이라 체감 차이가 없다.
- 오답 보기는 무작위 후보라, 정답과 여러 속성이 다른 경우가 많아 대충 골라도 맞기 쉽다.
- 보호자: "설명할 규칙이 없다. 두뇌 게임이라 할 수 없다."

## 목표
각 속성(모양, 색, 개수, 방향)이 **서로 다른 규칙으로 따로 움직이고**, 아이가 규칙을 **말로 설명할 수 있는** 문제를 낸다. 오답 보기는 두 속성의 2×2 조합을 기본으로 쓰되, 요령 방지 기준을 만족하지 못하면 보인 속성값의 다른 네 보기 조합을 허용해 보기끼리 닮은 정도나 처음 보는 값만으로 정답을 고를 수 없게 한다. 아이는 두 속성의 규칙을 확인해야 정답을 고를 수 있다.

## 범위
**포함**
- 생성기를 새로 만든다(`pattern.ts`). 화면은 기존 보기 4개·키보드(1~4, Enter) 방식을 유지하고, 격자 문제용 그리기만 추가한다.
- 새 속성 **방향**: 화살표 모양(`arrow`)만 방향(0°/90°/180°/270°)을 가진다.
- 풀고 난 뒤(정답 또는 정답 보기) **규칙 설명**을 한국어 한두 줄로 보여 준다. 예: "모양: 동그라미 → 세모 → 네모 반복 · 색: 2칸마다 바뀜 · 개수: 1씩 늘어남".
- 힌트(기존 2분 규칙)는 규칙 종류만 알려 준다. 예: "모양과 색이 서로 다른 박자로 바뀌어요."

**제외** (하지 말 것)
- 다른 퍼즐 변경, 저장 구조 변경(레벨 기록은 그대로 `pattern` 키 사용)
- 이미지 파일, 외부 라이브러리

## 설계
### 규칙 종류 (속성별로 하나씩 고름)
| 규칙 | 설명 | 예 |
|---|---|---|
| `fixed` | 바뀌지 않음 | 색이 계속 파랑 |
| `cycle(k)` | k개 값을 차례로 반복 (k = 2~4) | 동그라미, 세모, 네모, 동그라미… |
| `step(+d)` | 1씩(또는 2씩) 늘어남/줄어듦, 개수 1~6 범위 안 | 개수 1, 2, 3, 4… |
| `turn(θ)` | 화살표가 90°(또는 180°)씩 돈다 | → ↓ ← ↑ |

### 단계별 구성
| 단계 | 형태 | 규칙 조합 | 보여 줄 칸 |
|---|---|---|---|
| ★1 | 한 줄 | 속성 1개만 `cycle(2~3)`, 나머지 `fixed` (지금과 비슷, 둘째 시작) | 2바퀴 + 1 |
| ★2 | 한 줄 | 모양 `cycle(3)` + 색 `cycle(2)`처럼 **박자가 다른 두 반복** (묶음 통째 반복 금지: 두 주기가 서로 달라야 함) | 각 반복이 2바퀴 이상 보이도록 (보통 7~8칸) |
| ★3 | 한 줄 | `step` 또는 `turn` 1개 + `cycle` 1개 | `step`/`turn`은 4칸 이상 보임 |
| ★4 | 3×3 격자, 빈칸 1개 | 모양 라틴 방진 + 대각선(행−열) 개수 `step(±1)`: 아래로 한 칸 가면 늘고 오른쪽으로 한 칸 가면 줄거나, 그 반대. 개수 1~6 | 8칸 |
| ★5 | 3×3 격자, 빈칸 1개 | 대각선(행+열) 색 `cycle(4)` + 열 방향 개수 `step(±1)` + 모양 라틴 방진 또는 행 방향 `turn` | 8칸 |

- 첫째의 처음 단계는 ★2(지금 규칙과 같음), 둘째는 ★1. 저장된 레벨은 그대로 쓴다.
- 격자 빈칸 위치는 무작위(마지막 칸만 고정하지 않음). 규칙 후보가 서로 다른 답을 예측하는 위치는 다시 뽑는다. ★4의 개수 대각선 양 끝(오른쪽 위·왼쪽 아래)은 step과 cycle(4)의 답이 충돌하여 제외될 수 있다.
- 격자에는 같은 행·열의 칸을 복사해서는 맞힐 수 없는 속성을 하나 이상 둔다(★4 개수, ★5 색).
- 라틴 방진을 쓰는 판은 풀이 중에도 "가로줄과 세로줄에 같은 모양은 한 번씩 나와요"라는 약속을 알려 준다. 화살표 판에는 이 안내를 넣지 않는다.

### 답이 하나로 정해질 것
- 순수 함수 `consistentRules(sequenceOrGrid, attribute): Rule[]`: 보여 준 칸과 맞는 규칙 후보를 모두 찾는다(위 규칙 표 범위 안에서).
- 생성한 문제는 **모든 속성에서 후보 규칙들이 다음 칸(빈칸)에 같은 값을 예측**해야 한다. 아니면 칸을 늘리거나 다시 뽑는다(재시도 상한 + 단계별 안전한 고정 문제로 대체).

### 오답 보기 3개 (2026-10-10 PR #57 리뷰 후 보호자 확인)
- 속성 두 개 X, Y를 골라 **2×2 조합을 기본**으로 만든다: (정답X, 정답Y), (오답X, 정답Y), (정답X, 오답Y), (오답X, 오답Y). 오답 둘은 속성 하나가 다르고, 나머지 하나는 속성 둘이 다르다.
- 가능한 한 움직이는 두 속성을 고르고, 속성 쌍은 판마다 바꾼다. ★1은 움직이는 속성이 하나이므로 고정 속성도 함께 쓸 수 있다.
- 바꾼 값은 "그럴듯한 실수"를 우선한다: 한 박자 앞/뒤의 값, `step`을 한 번 덜/더 간 값, 반대 방향.
- 오답의 속성값은 해당 속성에서 **이미 보인 대체 값**을 먼저 쓴다. 보인 대체 값이 없을 때만 새 값을 쓴다. 한 박자 앞/뒤, step 한 번 덜/더, 반대 방향 순으로 우선한다.
- 이미 나온 타일과 같은 오답도 허용하되, 그 보기를 제거해서 정답만 남거나 정답의 유사도가 높아지는 조합은 피한다.
- **예외 조합(2026-10-10 재리뷰 후 보호자 확인):** ★2의 8칸과 2×2를 엄격히 유지하면 처음 보는 값과 과거 타일을 모두 제거한 찍기 적중률을 40% 이하로 만들 수 없다. 2×2 후보가 기준을 통과하지 못하면 보인 속성값(정답의 값 포함)을 조합해 다른 보기 네 개를 만든다. 오답은 여전히 정답과 속성 하나 또는 둘만 다르게 한다.
- 보기 후보 검사도 상한을 둔다(최대 7,000조합). 못 찾으면 판을 다시 뽑고, 판 생성 상한 뒤에는 단계별 검증된 고정 판·보기를 쓴다.
- 보기 4개는 모두 다르고, 규칙을 모두 만족하는 것은 정답 하나뿐이다.
- 단계별 200판에서 "다른 보기들과 가장 많이 겹치는 보기" 요령의 적중률은 35% 이하, "앞 칸에 나온 보기를 제외한 뒤 같은 요령"은 40% 이하로 검사한다. 동점의 무작위 선택 기대값과 첫 보기 선택을 모두 확인한다. 제거 뒤 남은 보기로 점수를 다시 계산하는 방식과 최초 점수를 유지하는 방식 둘 다 검사한다.
- ★2~5 각 200판에서 "처음 보는 속성값이 들어간 보기를 제거한 뒤 찍기"와 "그 뒤 과거 타일까지 제거한 뒤 찍기"의 기대 적중률은 각각 40% 이하로 검사한다. 과거 타일만 제거한 찍기도 40% 이하로 유지한다. ★1은 입문 단계라 이 필터 기준에서 제외한다.
- 예외 보기에서 반대 요령이 생기지 않도록 "가장 덜 겹치는 보기"와 "과거 타일 제거 뒤 가장 덜 겹치는 보기"도 기대 적중률 40% 이하로 검사한다.

### 데이터 모양
```ts
export type PatternShape = 'circle' | 'triangle' | 'square' | 'star' | 'arrow';
export interface PatternTile { shape: PatternShape; color: PatternColor; count: number; dir?: 0 | 90 | 180 | 270 }
export type PatternRule = ({ kind: 'fixed' } | { kind: 'cycle'; values: unknown[] } | { kind: 'step'; delta: number } | { kind: 'turn'; deg: 90 | 180 }) & { axis?: 'row' | 'column' | 'diagonal' | 'anti-diagonal' };
export interface PatternView {
  layout: 'row' | 'grid';
  cells: (PatternTile | null)[];        // row: 앞에서부터, grid: 9칸(빈칸 하나 null)
  options: PatternTile[];               // 4개
  rules: Partial<Record<'shape' | 'color' | 'count' | 'dir', PatternRule>>;  // 풀이 설명용(화면에는 풀고 난 뒤에만)
}
export function explainRules(view: PatternView): string;   // 한국어 설명 한두 줄
```
- 예전 `PatternView`(`sequence`, `period`)로 저장된 진행 중 퍼즐이 있으면 새 퍼즐로 바꾼다.
- 그리기: 타일 아래 텍스트 라벨("파랑 동그라미 2개")은 화면에서 숨기고 스크린 리더용(`aria-label`)으로만 둔다. 보이면 그림 대신 글자를 읽고 풀게 된다.
- 개수는 최대 6개까지 2줄로 그린다. 화살표는 SVG 회전.
- ★1~3은 풀이 순서를 유지하며 칸을 줄바꿈한다. 폰에서 추가 스크롤 없이 물음표까지 모두 볼 수 있게 하고, 칸 최소 44px를 지킨다.
- 회전 설명은 각도보다 보이는 방향 순서("→ ↓ ← ↑ 순서로")나 "한 칸마다 반대쪽을 봐요"처럼 쓴다.

## 수용 기준
- [ ] ★2 이상에서는 "묶음 통째 반복"으로 풀리는 문제가 나오지 않는다: 어떤 고정 길이 p에 대해서도 `cells[i] = cells[i - p]`로 빈칸이 맞혀지지 않는다(★2~3, 생성 200회 테스트).
- [ ] 단계별 문제 형태와 규칙 조합이 표와 같다(생성 200회 테스트). ★4~5는 같은 행·열의 칸을 복사해서는 맞힐 수 없는 속성이 하나 이상 있다.
- [ ] 모든 속성에서 가능한 규칙 후보가 빈칸에 같은 값을 예측한다(`consistentRules` 테스트, 생성 200회).
- [ ] 보기는 두 속성의 2×2를 기본으로 하고 필요시 보인 값의 다른 조합을 허용하며, 규칙을 모두 만족하는 보기는 정답 하나뿐이다. 단계별 200판에서 보기 중심 요령 35% 이하, 과거 타일 제외 뒤 같은 요령 40% 이하. ★2~5는 처음 보는 값 제거·과거 타일까지 제거한 찍기 각각 40% 이하이며, 반대 유사도 요령도 40% 이하(테스트).
- [ ] 풀고 난 뒤 규칙 설명이 나오고, 풀이 중에는 나오지 않는다. 힌트는 규칙 종류만 알려 준다.
- [ ] 풀이 중 화면에 타일 설명 글자가 보이지 않는다(스크린 리더용 라벨은 유지).
- [ ] 같은 시드 → 같은 퍼즐, 재시도 상한 후 대체 문제(테스트). 예전 형식의 진행 중 퍼즐은 새 퍼즐로 바뀐다.
- [ ] 375px·DeX·다크 모드에서 한 줄 문제의 모든 칸과 3×3 격자·보기가 추가 가로 스크롤 없이 잘 보이고(칸 최소 44px), 마우스·터치·키보드(1~4, Enter)로 풀 수 있다.
- [ ] 퍼즐 기록·레벨 조절·보상 분리는 그대로다.
- [ ] `npm run lint && npm run typecheck && npm test && npm run build` 통과

## 리뷰 포인트
- 규칙이 정말 "말로 설명할 수 있는" 규칙인지, 답이 둘 이상으로 해석될 여지가 없는지(생성 예시 10개 이상을 PR 본문에 글로 적기)
- 기본 2×2와 예외 보기에서 속성의 규칙을 확인해야 풀리는지, 보기의 유사도나 처음 보는 값만으로 정답이 드러나지 않는지
- 초3(★1~2)과 초5(★2~5)에 맞는 난이도인지는 **배포 후 아이들 반응**으로 조정
