# T24 — 실제 기기 맞춤: 아이 태블릿·아이폰·QHD 모니터

- 상태: 준비됨 · 2026-10-10 작성
- 단계: 유지
- 선행 작업: 없음 (T22b와 동시에 진행 가능, `styles.css` 충돌은 나중에 머지하는 쪽이 정리)
- 예상 분량: T24a 반나절~하루 / T24b 반나절

## 목표
가족이 실제로 쓰는 네 가지 화면에서 글씨, 버튼, 퍼즐 크기가 알맞고 소리, 마이크, 저장이 안정적으로 동작하게 한다. 지금까지 기준으로 삼은 Galaxy Fold4 + DeX를 실제 기기로 바꾼다.

## 배경
기획 초기에는 아이들이 Fold4 + DeX를 쓴다고 가정하고 375px 폰과 DeX 큰 화면으로만 검증했다. 실제 기기는 아래와 같다.

| 사용자 | 기기 | 화면(물리) | 예상 CSS 화면 | 브라우저·입력 |
|---|---|---|---|---|
| 첫째·둘째 | 아이뮤즈 뮤패드 K10 PLUS (Android 13, Helio G99, RAM 4GB) | 10.4인치 2000×1200 | 가로 약 1333×800, 세로 약 800×1333 (DPR 1.5 추정, **실기기에서 확인**) | Chrome, 터치만 (키보드 없음) |
| 보호자 | 아이폰 14 | 6.1인치 | 390×844, 노치·홈 바 | Safari 또는 홈 화면 앱, 터치 |
| 보호자(배우자) | 아이폰 13 | 6.1인치 | 390×844, 노치·홈 바 | 위와 같음 |
| 공통 | PC 모니터 | 2560×1440 | 2560×1440(100%) 또는 2048×1152(125%) | Chrome/Edge, 마우스·키보드, 마이크는 헤드셋 |

코드를 확인한 결과 문제는 아래와 같다.
1. **아이콘**: `icon.svg` 하나뿐이다. 아이폰 홈 화면 아이콘은 SVG를 쓰지 않는다(`apple-touch-icon` PNG 필요). 안드로이드 설치 아이콘도 PNG 192/512와 maskable 버전이 있어야 안정적이다.
2. **큰 화면**: 모든 화면이 `.page { max-width: 760px }` 한 칸이다. 2560 모니터에서는 가운데 좁은 띠에 작은 글씨로 보이고, 퍼즐판(`max-width: 390px`)과 블록 그림(360px)이 손바닥만 하다.
3. **아이폰 안전 영역**: 위쪽(`safe-area-inset-top`)만 처리한다. 가로 모드 노치와 아래 홈 바 영역은 처리하지 않는다.
4. **아이폰 홈 화면 앱의 음성 인식**: iOS 홈 화면 앱(standalone)에서는 `webkitSpeechRecognition`이 없거나 동작하지 않는다는 보고가 있다. 실시간 대화(WebRTC)와 별개로 따라 말하기, 먼저 고쳐 보기, 말하기 채점 같은 🎤 기능이 막힐 수 있다. 지금은 기능별로 조용히 사라지거나 오류가 날 수 있다.
5. **저장**: `navigator.storage.persist()`를 요청하지 않는다. Safari 탭에서는 7일 동안 쓰지 않으면 데이터가 지워질 수 있다. Safari 탭과 홈 화면 앱은 저장 공간이 서로 다르다. 기기 사이 동기화도 없다(T14).
6. **태블릿 성능**: 오비 달리기와 낚시 게임은 `requestAnimationFrame`으로 계속 그리는데, 앱이 백그라운드로 가도 멈추지 않는다(`visibilitychange` 처리 없음). RAM 4GB 기기에서는 발열과 끊김이 생길 수 있다.
7. 문서(`AGENTS.md`, `docs/PLAN.md`, `docs/REVIEW.md`)가 Fold4 + DeX와 375px 기준이었다. 이 명세와 함께 고쳤다.

## 범위
### T24a — 화면 맞춤 (CSS·아이콘·문서)
**포함**
- **아이콘**: `public/`에 PNG 아이콘을 추가한다.
  - 180(apple-touch-icon), 192, 512, maskable 512(안쪽 80% 안전 영역)
  - SVG를 원본으로 해서 빌드 시점 스크립트가 아니라 **한 번 만든 PNG를 커밋**한다. 새 의존성은 금지한다. 생성 방법은 PR에 적는다.
  - `index.html`에 `apple-touch-icon`, `apple-mobile-web-app-title`(학습스테이션), `apple-mobile-web-app-status-bar-style`(default)을 추가한다. manifest `icons`에 PNG를 추가하고 SVG도 유지한다.
- **안전 영역**: `.page`의 좌우와 아래 padding에 `env(safe-area-inset-*)`를 `max()`로 반영한다. 모달 배경(`position: fixed`)도 같이 처리한다. `min-height: 100vh`는 `100dvh`로 바꾸고 `100vh`를 대체 값으로 남긴다.
- **화면 크기 단계**: CSS 변수로 기준값을 정한다. 숫자는 시작값이며, 화면 확인 후 조정할 수 있다.

  | 이름 | 조건 | 본문 글자 | `.page` 최대 폭 | 메모 |
  |---|---|---|---|---|
  | 폰 | ~599px | 16px | 100% | 지금 그대로 |
  | 태블릿 | 600~1199px | 17px | 960px | 퍼즐·게임 판을 화면 높이에 맞춤 |
  | 큰 화면 | 1200~1799px | 18px | 1080px | |
  | QHD | 1800px~ | 20px | 1280px | 2560×1440(100%) |

  - 루트 `font-size`를 단계별로 올려서 rem 기반 요소가 같이 커지게 한다. px로 고정된 퍼즐 칸, 숫자 키, 아이콘은 `clamp()`나 CSS 변수로 바꾼다.
  - 퍼즐판, 블록 그림, 빙고판, 도형 규칙, 오비·낚시 판은 `min(가용 폭, 가용 높이 - 상단바·버튼 높이)`에 맞춰 커진다. **태블릿 가로(약 1333×800)에서 스크롤 없이 판 전체와 확인 버튼이 한 화면에 보여야 한다.**
  - 홈 화면의 미션 카드는 태블릿 이상에서 2열, QHD에서 3열 격자로 바꿀 수 있다. 순서는 바꾸지 않는다.
  - 대화 화면의 자막과 누르고 말하기 버튼은 큰 화면에서 폭을 720px 안팎으로 제한해 읽기 좋게 한다.
- **터치 기준**: 아이 화면에서 누를 수 있는 요소는 최소 48×48px로 한다(지금 44px인 퍼즐 칸 포함, 폰은 예외로 44px까지 허용). 태블릿에는 키보드가 없으므로 숫자 입력은 화면 키패드만으로 끝까지 갈 수 있어야 한다(T15의 물리 키보드 지원은 PC용으로 유지).
- 문서(`AGENTS.md`, `docs/PLAN.md`, `docs/REVIEW.md`)의 기기 기준은 이 명세와 함께 이미 바꿨다. 예전 명세서의 "DeX" 문구는 기록이므로 고치지 않는다.

**제외**
- 기능 추가, 문구 변경, 레이아웃 순서 변경
- 가로/세로 고정(orientation lock)
- 새 CSS 프레임워크나 의존성

### T24b — 기기 기능 확인과 저장 보호
**포함**
- **기기 점검 화면**: 보호자 모드 "백업·보안" 탭 아래에 "이 기기 점검"을 추가한다. 순수 함수 `src/lib/deviceCheck.ts`의 `checkDevice(env)`가 결과를 만들고, 화면은 그 결과를 보여 준다.
  - 화면 크기(CSS px, DPR), 단계 이름, 세로/가로
  - 홈 화면 앱인지(`display-mode: standalone` 또는 `navigator.standalone`)
  - 음성 인식 있음/없음, 음성 읽기(TTS) 영어 목소리 개수, 마이크 권한 상태(`permissions.query`가 되면)
  - 저장 보호 상태(`navigator.storage.persisted()`), 사용량/여유(`storage.estimate()`)
  - 마지막 백업 날짜
  - 각 항목에 "괜찮아요 / 확인 필요 + 한 줄 해결법"을 붙인다. 예: "아이폰 홈 화면 앱에서는 음성 인식이 안 될 수 있어요. 따라 말하기는 ⌨️로 하거나 Safari에서 여세요."
  - "🔊 소리 시험"(TTS 한 문장), "🎤 마이크 시험"(3초 녹음 후 음량 막대, 녹음은 저장하지 않음) 버튼
- **음성 인식이 없을 때 통일된 처리**: `speech.ts`의 지원 여부 함수 하나로 판단한다. 🎤 버튼이 있는 모든 화면(말하기, 코치 따라 말하기, 먼저 고쳐 보기, 다시 말하기 예정 자리)은 다음처럼 동작한다.
  - 🎤 버튼을 숨기지 않고 비활성으로 두며 "이 기기에서는 음성 인식이 안 돼요" 한 줄과 ⌨️ 입력으로 바꿀 수 있게 한다. 아이 화면에서는 "글자로 써도 돼요"로 쓴다.
  - 인식을 시작했는데 오류(`not-allowed`, `service-not-allowed`, `audio-capture`)가 나면 같은 안내로 바꾼다. 무한 재시도는 하지 않는다.
  - 실시간 대화(WebRTC)는 음성 인식과 상관없이 그대로 쓸 수 있어야 한다.
- **저장 보호**:
  - 앱 첫 실행과 보호자 모드 진입 시 `navigator.storage.persist()`를 조용히 요청한다(지원할 때만, 실패해도 무시).
  - iOS Safari **탭**(홈 화면 앱이 아님)에서 열었을 때 보호자 화면에 "홈 화면에 추가하면 기록이 더 안전해요. Safari 탭과 홈 화면 앱은 기록이 따로예요. 옮기려면 백업 파일을 쓰세요" 안내를 한 번 보여 준다(닫으면 다시 안 보임).
  - 마지막 백업이 14일 이상 지났으면 보호자 화면 상단에 "백업한 지 n일 지났어요" 한 줄을 보여 준다.
- **애니메이션 절약**: 오비 달리기와 낚시 게임은 `document.hidden`이면 프레임 루프를 멈추고, 돌아오면 일시정지 상태로 재개한다(게임 시간은 흐르지 않게). 캔버스를 쓰는 경우 DPR을 최대 2로 제한한다.

**제외**
- 기기 간 동기화(T14), 네이티브 앱, 서버 쪽 음성 인식
- 아이 계정 관리, 다른 앱 잠금(유튜브 잠금 등)

## 설계
- 저장 데이터 변경(선택 필드, version 2 유지)
  ```ts
  // AppState.settings 또는 보호자 설정에 추가
  lastBackupAt?: string;      // 백업 내보내기 성공 시 YYYY-MM-DD
  iosTabNoticeDismissed?: boolean;
  ```
  - `normalizeState`: 날짜 형식과 불리언을 검사한다. 백업 파일에는 `lastBackupAt`을 포함하되, 가져오기 후에는 가져온 날짜로 덮어쓰지 않는다.
- `src/lib/deviceCheck.ts`: `window`에 직접 의존하지 않게 `env` 객체를 받는 순수 함수로 만들고 단위 테스트를 붙인다.
- CSS는 `src/styles.css` 안에서 단계별 `@media` 블록을 한곳에 모으고, 맨 위 `:root`에 단계 변수를 정의한다.

## 리뷰 포인트
- 단계별 글자 크기를 올리면서 기존 폰 화면(390px)이 바뀌지 않았는지
- `dvh`·안전 영역을 처리한 뒤 모달과 키패드가 아이폰 아래쪽에 가려지지 않는지
- 음성 인식 대체가 화면마다 따로 구현되지 않고 한 곳에서 판단되는지
- 아이콘 PNG가 저작권 문제 없는 자체 그림인지(기존 SVG에서 만든 것)
