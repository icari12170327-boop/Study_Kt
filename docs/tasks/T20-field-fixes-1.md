## T20a-1. 대화 종료 버그 (🔴 최우선)

### 현재 코드 흐름 (확인함)
- 앱: `TalkSession.tsx` `finish(run)` → `run.handle.stop()` → `src/lib/realtime.ts` `stop()`
  - `cleanup()`으로 마이크·`RTCPeerConnection`·데이터 채널을 **먼저 닫고**, 그다음 `POST /api/realtime/end { sessionId, seconds }`(keepalive)를 보낸다. 실패하면 `onError`만 부르고 끝.
- Worker: `/api/realtime/end` → `FamilyUsage.closeSession(id)` → `closeOnce(id)`
  - 세션이 아직 `ended`가 아니면 **먼저 OpenAI `hangup(callId)`를 부르고**, 성공한 뒤에야 `chargeSession`으로 종료 처리한다.
  - `hangup`이 404 말고 다른 오류(예: 클라이언트가 이미 연결을 끊어 400/409 등, 또는 5초 타임아웃)를 내면 예외가 나고, **이때 세션은 `ended`가 되지 않는다.** `needsHangup` 재시도 기록도 `ended && needsHangup`일 때만 남기므로 남지 않는다. 그래서 알람이 남은 시간 끝(`start + remaining`)까지 "진행 중"으로 둔다.
- 반대로 보호자 모드의 `/api/realtime/end-active`(`endActive`)는 **먼저 `chargeSession` + `needsHangup = true`로 종료 처리하고** 그다음 hangup을 시도한다. 그래서 보호자 모드에서는 잘 끝난다.

**추정 원인**: `/end` 경로가 "외부 hangup 성공"을 종료 조건으로 삼는다. 앱은 연결을 먼저 끊으므로 OpenAI가 hangup에 오류를 돌려줄 수 있고, 그러면 세션이 열린 채 남는다. Codex는 구현 전에 Worker 로그(`wrangler tail` 또는 테스트 재현)로 hangup 응답 코드를 확인하고, 다른 원인이 있으면 PR 본문에 적는다. 키나 토큰은 로그·PR에 남기지 않는다.

### 고칠 것
- Worker `/api/realtime/end`를 `endActive`와 같은 순서로 바꾼다.
  1. 잠금 안에서 바로 `chargeSession`, `ended = true`, `needsHangup = !!callId`
  2. 그다음 `hangup` 시도. 실패하면 기존 `needsHangup` + 점진 재시도 알람(5초 → 1분 → 10분)에 맡긴다.
  3. 응답은 hangup 결과와 관계없이 `{ ok: true, seconds }`
- `hangup`: 이미 끝난 통화로 보이는 응답(404 외에 OpenAI가 실제로 돌려주는 코드, 확인 후 결정)은 성공으로 본다.
- 앱 `realtime.ts` `stop()`:
  - `/end`가 실패하면(네트워크 등) 한 번 더 시도하고, 그래도 실패하면 `/api/realtime/end-active { profileId }`로 그 프로필 세션을 닫는다.
  - 순서는 그대로 둬도 된다(서버가 hangup 실패에 견디게 되므로). 단, `pagehide` 때도 같은 경로를 탄다.
- 앱 화면:
  - "끝내기" 뒤 대화 완료 화면에 서버 종료가 확인될 때까지 "대화를 정리하고 있어요…", 확인되면 사라진다.
  - 끝내 확인이 안 되면 "연결 정리가 안 됐어요. 보호자 모드 → AI 연결에서 끝내 주세요"와 바로가기(보호자 프로필일 때만).
- 대화 시작 화면에 들어올 때 그 프로필의 남은 세션이 서버에 있으면(`/api/realtime/active`) 자동으로 `end-active`를 부르고 시작한다. 지금은 `busy`(409) 오류로 막힌다.

### 수용 기준 (T20a-1)
- [ ] "끝내기"를 누르면 보호자 모드 "진행 중인 대화"에 그 대화가 남지 않는다(OpenAI hangup이 오류여도). Worker 테스트로 확인.
- [ ] hangup 실패 시 `needsHangup` 재시도가 저장되고, 세션은 `ended`이며 다음 대화가 `busy`로 막히지 않는다(테스트).
- [ ] 앱이 `/end` 실패 시 재시도와 `end-active` 대체 경로를 탄다(테스트, 가짜 fetch).
- [ ] 뒤로 가기, 앱 닫기(`pagehide`), 시간 다 됨, 오류로 끝날 때도 같은 종료 경로를 탄다.
- [ ] 이미 남아 있던 세션이 있으면 새 대화 시작 전에 자동으로 정리된다.
- [ ] 사용 시간 계산(`chargeSession`, `onCharged`)은 지금과 같은 값이 나온다(기존 테스트 유지).

## T20a-2. 목소리 선택

### 사실 확인 (OpenAI 실시간 음성의 한계)
- 쓸 수 있는 목소리는 정해진 10개(`alloy, ash, ballad, coral, echo, sage, shimmer, verse, marin, cedar`)이고 **진짜 어린이 목소리는 없다.**
- 그래서 "또래 아이"는 **젊고 밝은 목소리 + 말투 지시**로 흉내 낸다. 짧은 문장, 신나는 말투, 아이다운 표현("Whoa!", "That's so cool!")을 쓰게 하고, 말 속도는 지금 아이 설정(0.85)을 유지한다.

### 고칠 것
- 목소리 "스타일" 추가 (`shared/ai.ts` `persona.voiceStyle?: 'kid-boy' | 'kid-girl' | 'young-woman' | 'calm-man'`)
  - Worker `personas.ts`: 스타일별 말투 한 줄을 지시문에 덧붙인다.
    - `kid-boy` / `kid-girl`: "Sound like a cheerful 10–11 year-old friend: playful, energetic, short sentences, simple words. You are a kid, not a teacher."
    - `young-woman`: "Sound like a warm, friendly young woman in her late 20s: bright, encouraging, patient."
    - `calm-man`: 지금의 Alex 말투.
  - Worker `validation.ts`: `voiceStyle` 선택 필드, 아이 프로필은 `kid-boy`/`kid-girl`만, 보호자는 `young-woman`/`calm-man`만 허용.
- 앱 목소리 고르기를 영어 이름 대신 한국어 카드로 (`TalkRecords.tsx` "친구 목소리")
  - 아이: "👦 또래 남자아이"(`verse` + `kid-boy`), "👧 또래 여자아이"(`shimmer` + `kid-girl`). 고급 설정 접기 안에 기존 10개 목록은 그대로 둔다.
  - 기본값: 첫째 Max = 👦 또래 남자아이, 둘째 Lily = 👧 또래 여자아이. 지금은 첫째가 `marin`(여성적인 목소리)이라 이름과 안 맞는다.
    - **기존 저장값은 바꾸지 않는다.** 보호자가 직접 고른 값을 덮어쓰지 않도록, 저장된 목소리가 예전 기본값(`marin`/`coral`)이고 스타일이 없을 때만 새 기본값으로 옮긴다(`normalizeState`, 테스트).
  - 보호자(비즈니스·코치): 새 설정 "대화 상대 목소리" — "👩 젊고 친절한 여성"(`coral` + `young-woman`, 새 기본값) / "🧑 차분한 남성"(`cedar` + `calm-man`, 지금 값). 상대 이름도 함께 바뀐다(여성 `Emma`, 남성 `Alex`).
  - 실제 목소리 이름(`verse`, `shimmer`, `coral`)은 실사용 후 바꿀 수 있게 상수 한 곳(`src/lib/voices.ts`)에 모은다.
- "🔊 미리 듣기"는 이번에 만들지 않는다(실시간 연결 비용이 듦). 대신 설정 아래에 "다음 대화부터 바뀌어요"를 표시.

### 수용 기준 (T20a-2)
- [ ] 아이 설정에서 "또래 남자아이 / 또래 여자아이"를 고를 수 있고, 대화 요청에 목소리와 스타일이 함께 간다(테스트).
- [ ] 보호자 설정에서 "젊고 친절한 여성 / 차분한 남성"을 고를 수 있고, 비즈니스·코치 모드에 반영된다. 상대 이름이 Emma/Alex로 맞게 나온다.
- [ ] Worker가 프로필별로 허용되지 않은 스타일을 거부하고, 스타일 지시문이 들어간다(테스트).
- [ ] 예전 기본값만 새 기본값으로 옮겨지고, 보호자가 고른 값은 그대로다(정규화 테스트). version 2 유지.
- [ ] `npm run lint && npm run typecheck && npm test && npm run build`, `cd worker && npm run typecheck && npm test` 통과

## T20b-1. 스도쿠 6×6 → 5×5

- `src/content/puzzles/sudoku.ts`: ★4~5의 크기를 6에서 **5**로. 5는 상자로 나눌 수 없으므로 **가로·세로 줄만 겹치지 않는 5×5**(라틴 방진)로 만든다. ★1~3의 4×4(2×2 상자)는 그대로.
  - `SudokuView`에 상자가 없음을 나타내는 값(예: `boxRows = 1, boxCols = 5`를 "상자 없음"으로 쓰거나 `boxes: false`)을 두고, `solveSudoku`가 상자 검사를 건너뛰게 한다. 해가 하나뿐인지 확인하는 기존 방식은 그대로 쓴다.
  - 빈칸 수: ★4 9칸, ★5 12칸(지금 14/20보다 줄임). 실사용 후 조정.
- 화면: 5×5에서는 굵은 상자 선을 그리지 않고, 안내 문구를 "가로줄과 세로줄에 1~5가 한 번씩"으로 바꾼다. 칸 최소 44px 유지.
- 저장 호환: 예전 기록의 `sudoku` 레벨은 그대로 쓴다(크기는 레벨에서 정해지므로 저장 변경 없음). 진행 중이던 6×6 퍼즐이 저장돼 있으면 새 퍼즐로 바꾼다.

### 수용 기준 (T20b-1)
- [ ] ★4~5 스도쿠가 5×5(1~5)로 나오고, 가로·세로에 같은 수가 없으며 해가 하나뿐이다(난이도별 생성 200회 테스트).
- [ ] ★1~3 4×4는 이전과 같은 퍼즐이 나온다(같은 시드 회귀 테스트).
- [ ] 375px·DeX에서 5×5 칸이 44px 이상이고 키보드로 풀 수 있다.

## T20b-2. 블록 세기 그림 겹침

- `blocks.ts` `blocksGeometry`: x축과 y축의 화면 이동량을 다르게 해서(예: 화면x = x·28 − y·18 근처에서 조정) 서로 다른 칸의 기둥이 같은 화면 위치에 정확히 겹치지 않게 한다. 그리기 순서(뒤→앞, 아래→위)를 새 투영에 맞게 확인한다.
- 생성기: ★1~3에서는 어떤 블록이 **다른 기둥에 완전히 가려지는** 배치를 만들지 않는다(자기 기둥 위 블록에 가려지는 것만 허용, T06 원래 의도). 판정은 순수 함수, 재시도 상한 + 안전한 배치로 대체. ★4~5는 허용하되 지도로 풀 수 있어야 한다.
- 지도와 그림 방향 맞추기: 그림 바닥 칸과 "위에서 본 층 수" 지도 칸에 같은 표시(①②③…)를 붙이거나, 지도를 그림과 같은 각도로 보여 준다.

### 수용 기준 (T20b-2)
- [ ] `[[2,0],[0,1]]` 같은 배치가 ★1~3에서 생성되지 않는다(테스트).
- [ ] 새 투영에서 서로 다른 칸의 기둥이 같은 화면 x에 놓이지 않는다(테스트).
- [ ] 정답 = 높이 합, 같은 시드 → 같은 퍼즐(기존 테스트 유지).
- [ ] 375px·DeX·다크 모드에서 그림이 잘리지 않는다.
