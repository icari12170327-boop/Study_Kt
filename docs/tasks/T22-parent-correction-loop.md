# T22 — 보호자 영어 코칭: 연구 기반 "한 판" 구조와 교정 고리

- 상태: T22a 완료 (PR #60) · T22b **다음** · 2026-10-10 개정: 교수법 연구 반영, T22a/T22b로 나눔
- 단계: 2 (T04, T18 개선)
- 선행 작업: T04 비즈니스 프리토킹, T18 코치 모드, T20c
- 예상 분량: T22a 하루~하루 반 (Worker + 앱), T22b 하루 (앱 중심)

## 배경 (2026-10-10 보호자)
- "대충 개념 없이 막 말하는데 코칭이 전혀 없어서 실력이 늘지 의문이다. 체계적으로 대화하면서 실력을 늘리고 싶다."
- 지금 코치 모드는 대화를 이어 주는 데 집중하고, 틀린 영어를 고쳐 주지 않는다. 대화 뒤 "마무리 쓰기"는 AI가 쓴 쉬운 문장 3개라 **내 실수**와 상관없다.
- 비즈니스 모드는 지시문에 "대화 중에는 교정하지 말 것"이 있고, 대화 뒤 `biz-feedback`이 교정을 최대 5개 준다. 하지만 다음 대화와 이어지지 않는다.

## 보호자 결정
1. 대화 중 교정은 **자연스럽게 고쳐 말해 주기(리캐스트)만** 한다. 대화를 멈추고 다시 말하게 하지 않는다.
2. 코치 모드와 비즈니스 모드 **둘 다** 적용한다.

## 연구 근거와 설계 반영
| 근거 | 내용 | 이 명세에 반영한 것 |
|---|---|---|
| 교정 피드백 메타분석 (Russell & Spada 2006, Mackey & Goo 2007, Li 2010) | 말하기 중 교정은 전반적으로 효과가 있고, 나중 시험에서도 효과가 남는다 | 대화마다 교정을 빼먹지 않는다 |
| 리캐스트 vs 프롬프트 (Ammar & Spada 2006, Lyster 계열 연구) | 스스로 고치게 하는 **프롬프트**가 리캐스트보다 효과가 크고, 특히 **초보는 리캐스트를 교정으로 알아채지 못하는 경우가 많다** | 대화 중엔 리캐스트만(보호자 결정) 하되, ① 리캐스트를 **짧고 눈에 띄게**(바꾼 부분만, 한 군데만), ② 자막에서 바뀐 말 강조, ③ 대화 **뒤에** "먼저 직접 고쳐 보기"(프롬프트)를 넣는다 |
| 리캐스트가 잘 알아채지는 조건 (Philp 2003, Sheen 2006) | 짧을수록, 바꾼 곳이 적을수록 더 잘 알아챈다 | 리캐스트는 사용자 문장 전체를 다시 말하지 않고 **고친 부분이 들어간 짧은 한 마디**로 |
| 과제 전 준비 (pre-task planning 연구) | 미리 준비하면 더 정확하고 덜 막힌다 | 대화 전 1분 "오늘 쓸 표현 3개" 미리 보기 |
| 과제 반복 (Bygate; 반복 사이 피드백·성찰 연구) | 같은 과제를 다시 하면 유창성·어휘가 좋아지고, 그 사이에 피드백·성찰이 있으면 형태에 주의가 간다 | 대화 → 교정 → **같은 이야기 다시 말하기**(짧게) |
| 4/3/2 기법 (Nation 1989, de Jong & Perfetti 2011) | 같은 이야기를 시간을 줄여 다시 말하면 말하는 속도가 빨라지고 머뭇거림이 준다 | 다시 말하기는 **2분 → 1분 30초**로 줄여 두 번까지(선택) |
| 덩어리 표현 + 간격 두고 다시 꺼내기 (formulaic sequences, spaced retrieval 연구) | 자주 쓰는 표현 덩어리를 간격을 두고 **말로** 다시 꺼내면 말이 길어지고 유창해진다(초보 근거는 아직 적음) | 교정·미리 보기 표현을 1일 → 3일 → 7일 간격으로 다음 대화에서 다시 말하게 유도 |
| 말하기 실력 측정: CAF (복잡성·정확성·유창성) | 세 가지를 따로 재야 성장이 보인다 | 대화마다 간단한 지표 3개를 기록해 추세를 보여 준다 |

> 주의: 위 연구는 대부분 교실·소규모 연구다. 숫자(간격, 시간, 개수)는 출발점이고 **실사용 후 보호자 체감으로 조정**한다.

## T22a — 리캐스트, 오늘의 교정(먼저 고쳐 보기), 다시 꺼내기

### A. 대화 중 리캐스트 (`worker/src/personas.ts`, 두 모드)
- 사용자 영어에 실수가 있으면 다음 답 **맨 앞에서 고친 부분이 들어간 짧은 한 마디**로 자연스럽게 되받는다. 예: 사용자 "I invest 5 years." → "Oh, **you've been investing** for five years! …"
- 한 턴에 리캐스트 하나, 사소하고 뜻이 통하는 실수는 넘어가도 된다. 같은 실수를 반복하면 그때 리캐스트한다.
- "틀렸어요", "You should say", "The correct form is" 같은 말은 쓰지 않는다. 대화를 멈추거나 다시 말하라고 하지 않는다.
- 비즈니스 지시문의 "Do not correct English during the conversation" 문장은 위 규칙으로 바꾼다.
- 코치 모드의 기존 규칙(한국어 답 환영, 따라 말하기 빈도, 점수·문법 강의 금지)은 그대로.
- 앱 자막: 리캐스트를 시각적으로 강조하는 것은 T22b(사용자 문장과 비교가 필요해서).

### B. 오늘의 교정 3개 — "먼저 직접 고쳐 보기"
**Worker 새 생성 종류 `talk-corrections`** (보호자 전용, 하루 생성 한도 공유)
- 입력: `{ mode: 'coach' | 'biz', level: CoachLevel | 'biz', lines: { role: 'user' | 'ai', text }[] }` — 기존 `summaryLines`와 같은 제한. AI 줄은 문맥용.
- 출력:
```ts
{
  items: {                 // 0~3개
    said: string;          // ≤200, 사용자가 실제로 한 말(그대로 인용)
    better: string;        // ≤160, 같은 뜻의 쉬운 자연스러운 영어 한 문장
    focus: string;         // ≤40, better 안에서 고친 핵심 부분(예: "you've been investing") — better의 부분 문자열
    whyKo: string;         // ≤120, 한국어 한 줄 이유(문법 용어 최소)
    hintKo: string;        // ≤80, 스스로 고쳐 볼 때 줄 힌트(답을 말하지 않음, 예: "언제부터 지금까지 계속한 일이에요")
    pattern: 'tense' | 'article' | 'preposition' | 'word-order' | 'agreement' | 'word-choice' | 'missing-word' | 'korean' | 'other';
  }[];
  praiseKo: string;        // ≤120, 잘한 점 한 줄
}
```
- 지시문: 가장 도움이 될 실수 **최대 3개**(자주 틀리는 것, 다음에도 쓸 표현 우선). 한국어로 말한 줄은 `pattern: 'korean'`. 코치 레벨이면 `better`는 그 레벨에 맞게 쉽게. 회사명·사람 이름·연락처·금융 숫자는 일반 표현으로 바꾼다. 투자 조언 금지.
- **검증**: `said`가 사용자 줄 중 하나에 들어 있어야 하고(공백·대소문자·구두점 무시), `focus`는 `better`의 부분 문자열이어야 한다. 아니면 그 항목을 버린다.
- 테스트: 스키마, 보호자 전용, 지어낸 `said`·맞지 않는 `focus` 제거, 지시문 규칙.

**앱 화면** (`src/components/TalkCorrections.tsx`, 두 모드 완료 화면 공통)
- 대화가 끝나면 자동으로 한 번 요청. 실패하면 "다시 받기", 대화 기록은 그대로.
- 카드 하나씩 순서대로(한 번에 하나):
  1. **먼저 고쳐 보기(프롬프트)**: 내가 한 말 + `hintKo`를 보여 주고 "어떻게 고치면 좋을까요?" → 🎤 말하기(음성 인식) 또는 ⌨️ 입력, 또는 "모르겠어요"
  2. **정답**: `better`에서 `focus` 부분 굵게, `whyKo`. 내가 말한 답이 `better`와 비슷하면(`similarity.ts`) "직접 고쳤어요! 👏" 기록(`selfFixed: true`)
  3. **듣고 따라 말하기**: 🔊 듣기(`speech.ts`) → 🎤 따라 말하기(기존 따라 말하기 판정 재사용, 실패해도 넘어갈 수 있음)
  4. "내 표현에 저장"(기본 체크, `savePhrase`, source `교정`)
- 음성 인식이 안 되는 기기에서는 입력칸과 "모르겠어요"만으로도 끝까지 갈 수 있다.
- 맨 위에 `praiseKo`. 교정이 0개면 "오늘은 고칠 곳이 거의 없었어요 👏".
- 결과는 `TalkLog.corrections`에 저장, 보호자 기록 화면에서 다시 보기.
- 모드별 기존 화면: 코치의 "마무리 쓰기"는 교정 카드 **아래**로. 비즈니스 `BusinessFeedback`은 총평·다음 표현 유지, `corrections` 목록은 새 기록에서 숨기고(예전 기록은 그대로 표시). `biz-feedback` 스키마는 바꾸지 않는다.

### C. 다시 꺼내기 (간격 반복, 말로)
- 대상: 교정 `better`와 T22b의 미리 보기 표현. 각 항목에 `stage`(0~3)와 `dueDate`.
  - 처음 생기면 stage 0, dueDate = 다음 날
  - 다음 대화에서 **직접 말하면** stage +1, 다음 간격 1일 → 3일 → 7일 → (stage 3 성공 시) "익힘" 완료
  - 기회가 있었는데 못 말하면 stage 그대로, dueDate = 다음 날. 3번 연속 못 말하면 다음 간격으로 미루고(1주) 계속 유지
- 순수 함수 `pickReviewTargets(items, today)`: dueDate ≤ today인 것 중 오래 밀린 순, **최대 2개**. 같은 모드 우선.
- 대화 요청 `SessionRequest`에 선택 필드 `reviewTargets?: string[]`(각 ≤160자, 최대 2개, 보호자 모드에서만 — Worker 검증), 참고 데이터 태그로 감싼다.
- 지시문(두 모드): "처음 2~3분 안에, 사용자가 `<review_targets>`의 표현을 **직접 말하게 될** 질문이나 상황을 만든다. 표현을 먼저 말하거나 시험처럼 보이게 하지 않는다. 비슷하게 말하면 한 단어 칭찬. 못 써도 다시 요구하지 않는다."
- 대화가 끝나면 사용자 줄과 대상을 비교해 stage·dueDate를 갱신하고, 완료 화면에 "지난 표현 다시 쓰기: 2개 중 1개 성공 ✅".

### 저장 (선택 필드, version 2 유지)
```ts
// TalkLog에 추가
corrections?: {
  items: { said: string; better: string; focus: string; whyKo: string; hintKo: string; pattern: CorrectionPattern; selfFixed?: boolean }[];
  praiseKo: string;
  createdAt: string;
};
reviewResult?: { targets: string[]; reused: string[] };
// ProfileData(parent)에 추가 — 다시 꺼내기 목록(최대 60개, 익힘 완료는 30일 뒤 정리)
retrieval?: { id: string; text: string; source: 'correction' | 'preview'; mode: 'coach' | 'biz'; stage: 0 | 1 | 2 | 3; dueDate: string; misses: number; createdAt: string; learnedAt?: string }[];
```
- `normalizeState()`: 형식·길이·날짜 검사, 개수 제한, 백업 포함.

### 수용 기준 (T22a)
- [ ] 두 모드 지시문에 짧은 리캐스트 규칙(고친 부분이 든 짧은 한 마디, 한 턴 하나), 교정 표현 금지, 대화 멈춤 금지가 있다. 비즈니스의 "대화 중 교정 금지" 문장은 바뀌었다(지시문 테스트).
- [ ] 대화가 끝나면 교정 카드가 최대 3개, 한 장씩 "먼저 고쳐 보기 → 정답(고친 부분 굵게) → 듣고 따라 말하기 → 저장" 순서로 나온다. 음성 인식 없이도 끝까지 갈 수 있다.
- [ ] 직접 고친 답이 정답과 비슷하면 `selfFixed`가 기록된다(테스트).
- [ ] Worker `talk-corrections`가 보호자 전용이고, 사용자 줄에 없는 `said`와 `better`에 없는 `focus`는 버린다(테스트).
- [ ] 다시 꺼내기: `pickReviewTargets`(due, 최대 2개, 모드 우선)와 stage/dueDate 갱신(1→3→7일, 못 말함, 3번 연속 실패) 테스트. Worker는 `reviewTargets`를 보호자 모드에서만 받는다.
- [ ] 비즈니스 완료 화면: 새 기록은 교정 카드, 예전 기록은 기존 corrections 그대로. 코치의 마무리 쓰기는 교정 카드 아래에 남는다.
- [ ] `normalizeState`·백업 테스트, version 2 유지. 아이 대화는 바뀌지 않는다.
- [ ] 375px·DeX·다크 모드, 키보드로 카드 조작 가능.
- [ ] 앱·worker 검사 통과. 머지하면 Worker 자동 배포.

## T22b — 미리 보기, 다시 말하기(4/3/2 축소판), 리캐스트 강조, 성장 지표

### ② 미리 보기 (대화 전 1분)
- 대화 시작 화면에서 주제를 고르면 "오늘 쓸 표현 3개"를 보여 준다. 각 표현: 영어, 한국어 뜻, 🔊 듣기. "건너뛰기" 가능.
- 표현은 **앱에 들어 있는 주제별 표현 목록**에서 고른다(새 AI 호출 없음). `src/content/talk/chunks.ts`에 코치 주제(일상·업무·투자)와 비즈니스 상황별로 각 20개 이상, 보호자가 검토할 수 있게 PR 본문에 전체 목록을 적는다.
  - 고르는 규칙: 아직 다시 꺼내기 목록에 없는 것 우선, 같은 표현은 2주 안에 다시 안 나옴.
- 고른 3개는 대화 요청의 `previewChunks`(선택 필드, 최대 3개)로 보내고, 지시문은 "이 표현을 사용자가 쓸 기회가 생기도록 대화를 이끈다(먼저 말하지 않음)".
- 대화 중 사용자가 쓴 미리 보기 표현은 다시 꺼내기 목록에 stage 1로, 안 쓴 것은 stage 0으로 넣는다.

### ⑤ 다시 말하기 (교정 뒤 2분)
- 교정 카드를 다 본 뒤 "오늘 이야기를 2분 안에 다시 말해 볼까요?"(건너뛰기 가능).
- 이 단계는 **실시간 대화 연결 없이** 앱의 음성 인식으로 녹취만 한다(비용 없음). 음성 인식이 없는 기기는 입력칸.
- 화면에 오늘 교정 `better` 3개와 미리 보기 표현을 작게 띄워 둔다.
- 끝나면 사용 여부만 간단히 표시: "교정 표현 2/3 사용 ✅", 말한 단어 수. 원하면 "1분 30초로 한 번 더"(4/3/2 축소판).
- 다시 말하기에서 쓴 교정 표현도 다시 꺼내기 성공으로 친다.

### 리캐스트 강조 (자막)
- 사용자 줄 바로 다음 AI 줄이 사용자 줄과 단어가 많이 겹치면서 일부가 다르면(순수 함수 `detectRecast(user, ai)`), 자막에서 다른 부분에 밑줄과 작은 "✏️ 이렇게도 말해요" 표시를 한다. 대화는 멈추지 않는다.
- 판정이 애매하면 표시하지 않는다(틀린 강조보다 없는 게 낫다).

### ⑥ 성장 지표 (대화마다 저장, 주간 리포트에 표시)
- 유창성: 사용자 발화당 평균 영어 단어 수, 다시 말하기의 분당 단어 수
- 정확성: 교정 수 ÷ 사용자 영어 문장 수, "먼저 고쳐 보기" 성공률
- 복잡성/전환: 영어 비율(한국어 대비), 미리 보기·교정 표현 다시 쓰기 성공률
- 보호자 주간 리포트(T13)에 "보호자 영어" 칸 추가: 지난주 대비 ▲▼, 최근 4주 막대.

### 수용 기준 (T22b)
- [ ] 대화 전 미리 보기 3개(건너뛰기 가능)가 앱 표현 목록에서 규칙대로 나오고, `previewChunks`로 전달된다(Worker는 보호자 모드에서만 허용).
- [ ] 교정 뒤 다시 말하기(2분, 선택 1분 30초)가 실시간 연결 없이 동작하고, 교정·미리 보기 표현 사용 여부가 다시 꺼내기에 반영된다.
- [ ] `detectRecast` 테스트(명확한 리캐스트는 표시, 단순 맞장구·다른 문장은 표시 안 함)와 자막 밑줄 표시.
- [ ] 성장 지표가 대화마다 저장되고 주간 리포트에 보호자 영어 칸이 나온다(테스트).
- [ ] 주제별 표현 목록 전체가 PR 본문에 있고 보호자 검토 후 머지.
- [ ] `normalizeState`·백업, version 2 유지, 검사 통과.

## 리뷰 포인트
- 리캐스트가 대화를 끊거나 수업처럼 되지 않는지, 초보 코치 레벨에서 너무 잦지 않은지
- "먼저 고쳐 보기"가 부담스럽지 않은지(언제든 "모르겠어요"로 넘어갈 수 있는지)
- `said`/`focus` 검증이 지어낸 교정을 막는지, 개인정보·금융 숫자가 카드에 남지 않는지
- 간격 반복이 실제로 1→3→7일로 도는지, 목록이 끝없이 쌓이지 않는지
- 실제 체감(리캐스트 빈도, 교정 품질, 다시 말하기 부담)은 **배포 후 보호자가** 일주일 써 보고 조정
