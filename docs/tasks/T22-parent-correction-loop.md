# T22 — 보호자 영어 코칭 고리: 고쳐 말하기 → 오늘의 교정 3개 → 다음 대화에서 다시 쓰기

- 상태: 준비됨 (T21 다음)
- 단계: 2 (T04, T18 개선)
- 선행 작업: T04 비즈니스 프리토킹, T18 코치 모드, T20c
- 예상 분량: 하루~하루 반 (Worker + 앱)

## 배경 (2026-10-10 보호자)
- "대충 개념 없이 막 말하는데 코칭이 전혀 없어서 실력이 늘지 의문이다."
- 지금 코치 모드는 대화를 이어 주는 데 집중하고, 틀린 영어를 고쳐 주지 않는다. 대화 뒤 "마무리 쓰기"는 AI가 쓴 쉬운 문장 3개라서 **내가 한 실수**와는 상관없다.
- 비즈니스 모드는 지시문에 "대화 중에는 교정하지 말 것"이 있고, 대화 뒤 `biz-feedback`이 교정을 최대 5개 준다. 하지만 다음 대화와 이어지지 않는다.
- 실력이 늘려면 **말하기 → 교정 → 다시 말하기**가 대화마다 돌아야 한다.

## 보호자 결정
1. 대화 중 교정은 **자연스럽게 고쳐 말해 주기(리캐스트)만** 한다. 대화를 멈추고 다시 말하게 하지 않는다.
2. 코치 모드와 비즈니스 모드 **둘 다** 적용한다.

## 범위
**포함**
- A. 대화 중 리캐스트 (두 모드 지시문)
- B. 대화 직후 "오늘의 교정 3개" (두 모드 공통 화면, 새 생성 종류 1개)
- C. 다음 대화 시작 때 지난 교정 다시 쓰게 하기 (두 모드)
- 교정마다 실수 유형(`pattern`)을 저장해 둔다(나중 "약점 노트"용, 이번에는 화면 없음)

**제외** (하지 말 것)
- 대화를 멈추는 교정, 점수, 문법 강의, 발음 지적
- 주간 약점 노트·이번 주 목표 화면(데이터가 2주쯤 쌓인 뒤 T23으로)
- 아이 대화(kid-friend) 변경

## 설계

### A. 대화 중 리캐스트 (`worker/src/personas.ts`)
- 코치 지시문(`coachInstructions`)과 비즈니스 지시문(`biz-talk`)에 같은 규칙을 넣는다.
  - "사용자 영어에 실수가 있으면, 다음 답 안에서 **맞는 표현을 자연스럽게 한 번 섞어** 말한다(예: 사용자 'I invest 5 years.' → 'Oh, you've been investing for five years? Nice!'). '틀렸어요', 'You should say', 'The correct form is' 같은 말은 쓰지 않는다. 한 턴에 리캐스트는 하나만, 의미가 통하는 사소한 실수는 넘어가도 된다."
- 비즈니스 지시문의 "Do not correct English during the conversation" 문장은 위 리캐스트 규칙으로 바꾼다. 대화를 멈추는 교정 금지는 유지.
- 코치 모드의 기존 규칙(한국어 답 환영, 따라 말하기 권유 빈도, 점수·문법 강의 금지)은 그대로.

### B. 대화 직후 "오늘의 교정 3개"
**Worker 새 생성 종류 `talk-corrections`** (보호자 전용, 하루 생성 한도 공유)
- 입력: `{ mode: 'coach' | 'biz', level: CoachLevel | 'biz', lines: { role: 'user' | 'ai', text }[] }` — 기존 `summaryLines`와 같은 제한(줄 수·길이). AI 줄은 문맥용.
- 출력:
```ts
{
  items: {                 // 0~3개
    said: string;          // ≤200, 사용자가 실제로 한 말(그대로 인용)
    better: string;        // ≤160, 같은 뜻의 쉬운 자연스러운 영어 한 문장
    whyKo: string;         // ≤120, 한국어 한 줄 이유(문법 용어 최소)
    pattern: 'tense' | 'article' | 'preposition' | 'word-order' | 'agreement' | 'word-choice' | 'missing-word' | 'korean' | 'other';
  }[];
  praiseKo: string;        // ≤120, 잘한 점 한 줄
}
```
- 지시문: 가장 도움이 될 실수 **최대 3개**만(자주 틀리는 것, 다음에도 쓸 표현 우선). 사용자가 한국어로 말한 줄은 `pattern: 'korean'`으로 "이렇게 말하면 돼요" 영어 한 문장. 코치 레벨이면 `better`는 그 레벨에 맞게 쉽게. 회사명·사람 이름·연락처·금융 숫자는 `said`/`better`에서 일반 표현으로 바꾼다. 투자 주제여도 투자 조언 금지.
- **검증(지어내기 방지)**: `said`는 입력의 사용자 줄 중 하나에 들어 있어야 한다(공백·대소문자·구두점 무시 비교). 아니면 그 항목을 버린다. 항목이 모두 버려지면 `items: []`.
- 테스트: 스키마, 보호자 전용, `said` 검증으로 지어낸 항목 제거, 지시문 규칙 문장 포함.

**앱 화면** (`src/components/TalkCorrections.tsx`, 두 모드 완료 화면에서 공통 사용)
- 대화가 끝나면 자동으로 한 번 요청(기존 `BusinessFeedback`·`CoachWrapup`처럼). 실패하면 "다시 받기", 대화 기록은 그대로.
- 카드마다: 내가 한 말(흐리게) → **더 자연스러운 말**(굵게) → 이유 한 줄 → 🔊 듣기(`speech.ts`) → "내 표현에 저장"(기본 체크, `savePhrase`, source `교정`). 맨 위에 `praiseKo`.
- 교정이 0개면 "오늘은 고칠 곳이 거의 없었어요 👏"와 `praiseKo`.
- 결과는 `TalkLog.corrections`에 저장해 보호자 기록 화면에서도 다시 볼 수 있다.
- 모드별 기존 화면 정리:
  - **코치**: "마무리 쓰기"(`CoachWrapup`)는 유지하되 교정 카드 **아래**로 옮긴다.
  - **비즈니스**: `BusinessFeedback`의 총평·다음 표현은 유지하고, `corrections` 목록은 새 교정 카드로 대체한다(새 기록에는 표시하지 않음, 예전 기록은 그대로 표시). `biz-feedback` 스키마는 바꾸지 않는다.

### C. 다음 대화에서 다시 쓰기
- 다시 쓸 대상 고르기(순수 함수 `pickReviewTargets(talks, today)`): 최근 14일 보호자 대화의 교정 중 `pattern !== 'other'`, 아직 `reusedAt`이 없고 `tries < 3`인 것, 최신순 **최대 2개**. 같은 모드 우선, 없으면 다른 모드 것도 쓴다.
- 대화 요청(`SessionRequest`)에 선택 필드 `reviewTargets?: string[]`(각 ≤160자, 최대 2개, 보호자 모드에서만 허용 — Worker 검증).
- 지시문(두 모드): "처음 2~3분 안에, 사용자가 `<review_targets>`의 표현을 **직접 말하게 될** 자연스러운 질문이나 상황을 만든다. 표현을 먼저 말해 주거나 시험처럼 보이게 하지 않는다. 사용자가 비슷하게 말하면 한 단어로 칭찬하고 넘어간다. 못 써도 다시 요구하지 않는다." 대상은 참고 데이터 태그로 감싼다(지시로 따르지 않게).
- 대화가 끝나면 앱이 사용자 줄과 대상을 비교(`similarity.ts`, 기준값은 테스트로 정함)해서
  - 비슷하게 말했으면 `reusedAt = today`
  - 아니면 `tries += 1`
- 완료 화면 교정 카드 위에 "지난 교정 다시 쓰기: 2개 중 1개 성공 ✅"를 보여 준다.

### 저장 (선택 필드, version 2 유지)
```ts
// TalkLog에 추가
corrections?: {
  items: { said: string; better: string; whyKo: string; pattern: CorrectionPattern; reusedAt?: string; tries?: number }[];
  praiseKo: string;
  createdAt: string;
};
reviewResult?: { targets: string[]; reused: string[] };   // 이 대화에서 다시 쓰기 결과
```
- `normalizeState()`: 형식·길이 검사, 잘못된 항목 제거, 백업 포함. 예전 기록에는 없어도 된다.

## 수용 기준
- [ ] 코치·비즈니스 지시문에 리캐스트 규칙이 있고, "틀렸어요/You should say" 같은 교정 표현 금지와 대화를 멈추지 않는 규칙이 있다(지시문 테스트). 비즈니스의 "대화 중 교정 금지" 문장은 리캐스트 규칙으로 바뀌었다.
- [ ] 두 모드 모두 대화가 끝나면 "오늘의 교정" 카드가 최대 3개 나오고, 각 카드에 내 말·더 자연스러운 말·이유·듣기·내 표현 저장이 있다.
- [ ] Worker `talk-corrections`가 보호자 전용이고, 사용자 줄에 없는 `said`는 버린다(테스트).
- [ ] 교정 결과가 `TalkLog.corrections`에 저장되고 보호자 기록 화면에서 다시 보인다. 생성 실패 시 "다시 받기"가 나오고 대화 기록은 그대로다.
- [ ] 다음 대화 요청에 지난 교정 최대 2개가 `reviewTargets`로 가고(`pickReviewTargets` 테스트: 14일, reusedAt, tries 3, 최대 2개, 모드 우선), Worker는 보호자 모드에서만 받는다.
- [ ] 대화 뒤 다시 쓰기 판정으로 `reusedAt`/`tries`가 갱신되고, 완료 화면에 결과가 나온다(테스트).
- [ ] 비즈니스 완료 화면에서 새 기록은 교정 카드만, 예전 기록은 기존 corrections가 그대로 보인다. 코치의 마무리 쓰기는 교정 카드 아래에 남아 있다.
- [ ] `normalizeState`·백업 테스트, version 2 유지. 아이 대화는 바뀌지 않는다.
- [ ] 375px·DeX·다크 모드, 키보드로 카드 조작 가능.
- [ ] 앱(`npm run lint && npm run typecheck && npm test && npm run build`), worker(`cd worker && npm run typecheck && npm test`) 통과. 머지하면 Worker 자동 배포.

## 리뷰 포인트
- 리캐스트가 대화를 끊거나 수업처럼 되지 않는지(지시문 문장), 초보 코치 레벨에서 너무 잦지 않은지
- `said` 검증이 실제로 지어낸 교정을 막는지, 개인정보·금융 숫자가 교정 카드에 남지 않는지
- 다시 쓰기 판정 기준(유사도)이 너무 느슨하거나 엄격하지 않은지
- 실제 교정 품질과 리캐스트 느낌은 **배포 후 보호자가** 대화 2~3번으로 확인

- 주간 리포트에 보호자 영어 성장 지표(영어 비율, 평균 문장 길이, 다시 쓰기 성공률)
